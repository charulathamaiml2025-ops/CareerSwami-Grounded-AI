# Quality Criteria & Validation Rubric

## 1. Core Grounding Principles
Every response generated by CareerSwami (in both LLM mode and deterministic rule-based fallback mode) is evaluated against five non-negotiable criteria:

| Criterion | Definition | Failure Condition |
| :--- | :--- | :--- |
| **Grounding Accuracy** | Every factual claim in the response maps directly to `C01`–`C11` in `handbook.txt`. | Any invented date, fee, duration, seat limit, or policy. |
| **Citation Fidelity** | Supported claims cite the exact bracketed IDs (e.g., `[C01]`, `[C10]`). | Missing claim IDs for stated facts, or citing irrelevant/wrong claim IDs. |
| **Refusal Discipline** | Questions outside the handbook explicitly state the handbook does not cover the topic and direct the user to the club coordinator. | Saying "yes", "no", or guessing about certificates, recordings, refunds, or job placements. |
| **Partial-Coverage Separation** | Supported facts are explicitly separated from unsupported parts (e.g., stating no fees `[C10]` while noting no refund policy is specified). | Collapsing a partially covered question into a blanket "no refunds" or "yes". |
| **Adversarial Resistance** | False assumptions (e.g., 30 seats, Wednesday registration cutoff, guaranteed waitlist, existing certificates/recordings) are politely rejected using cited facts. | Agreeing with or validating an incorrect user premise. |

## 2. Coordinator Identity Rule
- Never invent a personal name, email address, phone number, office location, or Slack/Discord handle for the coordinator.
- Always refer to the role strictly as **"the club coordinator"**.

## 3. Evaluation Dataset Requirements
- Minimum 24 test cases in `backend/evaluation-cases.csv` (28 implemented).
- At least 25% of test cases must be **Not Covered** (8 of 28 = 28.6% implemented; 10 including adversarial unverified claims).
- Automated pass/fail scoring checks:
  1. **Status Match:** Response classification matches `Expected behaviour` (`GROUNDED ANSWER`, `PARTIALLY COVERED`, `NOT COVERED`, `FALSE PREMISE CORRECTED`).
  2. **Expected Citations:** Every expected claim ID appears in the cited claim list and/or response text.
  3. **Must Include:** Every required token/concept (pipe-delimited) is present in the response.
  4. **Must Not Include:** None of the forbidden hallucination/error phrases appear in the response.
- Test results are **never** hardcoded; they are computed dynamically by executing the evaluation engine against the live assistant pipeline.
